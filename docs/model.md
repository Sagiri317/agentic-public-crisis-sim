# 公共危机理论与城市应急 Agent 模型

> 文件用途：模型实现和独立核查的科学规格，服务于遵守学术规范的公共危机管理机制仿真论文 / 研究报告。适用范围是一个总问题、三个研究问题。文献和课程材料支持问题选择；本文的节点、方程和参数是明确标注的合成设定，不冒充经验估计。

先读第1—2节理解研究，再读第3—9节检查模型，最后核对附录A的配置来源。实验格点、比较、随机种子、抽样与报告规则仅由 `experiment_protocol.md` 规定。

### 0.2 本文能说什么

研究总问题是：**局部自主失效如何经由业务和技术依赖转化为关键公共功能风险；在信息不完备、时限紧迫和处理能力有限时，监测处置、指挥配置与人工决策有哪些适用边界？**

三个研究问题分别是系统脆弱性、信息与监测处置、时间压力下的指挥配置与人机决策。模型不估计真实城市事故概率，不模拟完整洪水物理过程，不调用真实大模型，不测量个人领导风格，也不模拟公众信任、问责、灾后重建和长期组织学习。

### 0.3 输入合同

配置解析必须拒绝未知字段、非法枚举、重复节点/边、空功能、非正成员权重以及NaN/无穷。所有概率与比例均为有限实数且在[0,1]内；模型内部统一为float，输入`1`与`1.0`表示相同概率。布尔不是整数，`true`不得冒充容量1。

horizon、时限宽度、恢复/审核/指挥/拒绝时长和组数必须为正整数；release、shock_time、partition_seed为非负整数。仅人工容量允许`unlimited`，其他容量为正整数。节点/边/资源用户必须指向存在的ID，K不能超过该资源用户数。必要输入无环、消息延迟为正。schema检查在删除无消费者参数之前执行，不能借“反正当前没用”容忍非法值。

## 1. 公共危机管理依据与操作化边界

### 1.1 课程提供的分析框架

课程第一讲第14页提出局部功能性危机向整体系统性危机演化的问题。第二讲第7—8页强调严重威胁、快速决策、时间压力、信息的及时性与准确性以及资源不可利用性；第14页列出希斯4R、TIL和TIE；第19—20页同时要求控制事态蔓延、保持其他部门正常运转、综合信息和在有限信息下迅速决策。[C1–C2]

沿用课程的术语：4R为**减少、准备、响应、恢复**；TIL为**时间、信息、领导力**；TIE为**及时、全面、有效**。本文将“全面”的部分内容操作化为信息汇聚和跨环节检查，不把“全面”擅自改写成已经被完整测量的“整合指数”。4R与TIL是分析框架，不等于已经得到验证的定量因果定律。

| 课程概念 | 模型中实际处理的内容 | 不能由模型推出的结论 |
|---|---|---|
| 严重威胁、关键公共功能 | 七项业务功能的累计服务能力缺口 | 伤亡人数、经济损失或现实危机等级 |
| 信息不完备 | 已接受信息的覆盖与真实质量分开；信息等待和核验 | 现实信息环境的完整认知模型 |
| 时间与资源约束 | 任务到期、审核队列、服务时长、指挥瓶颈 | 模型时间步对应真实分钟、真实编制需求 |
| 领导作用 | 任务分诊规则及AI支撑的指挥许可/复核配置 | 人类领导力得分、政治制度优劣 |
| 减少、准备 | 共同依赖分组和预置控制能力 | 完整的防灾建设、成本收益分析 |
| 响应 | 检测、隔离、人工复核、短期纠错 | 完整救援现场的资源竞争与公众行为 |
| 恢复 | 技术完整性修复、有限行动回滚 | 灾后重建、问责、组织学习或反脆弱性 |

### 1.2 学术文献提供什么支持

Boin等将危机领导区分为态势理解、决策协调、意义建构、终止与问责、学习改革；本文只处理前两项中的有限机制。[R1] 张海波、童星的“目标—结构—过程”用于组织说明：目标是业务功能，结构是依赖与指挥配置，过程是信息、决策和处置，不能据此声称复制了其全部效能理论。[R2]

Comfort等的研究将核心信息与多组织响应联系起来，Lu与Xue讨论中国应急体系的共同态势理解；这支持同时表示正常信息的用途和错误传播，而非只建立污染网络。[R3–R4] Moynihan提示，层级与网络可能组合运行，其作用具有情境条件；因此本文比较具体的复核配置，不把“集中”“分散”直接标为领导能力高低。[R5]

公共组织韧性综述区分维持、恢复与适应。本文主要评价早期服务维持，不能把低损失自动写成长期韧性提高。[R6] Langer等的信号检测视角支持区分漏检和误拒绝，但不提供本模型的灵敏度、特异度数值。[R7]

2026年Margherita与Comes已明确讨论AI作为危机协调基础设施，并区分信息流、任务匹配和共享依赖。这意味着本文不能声称首次把AI与危机协调联系起来；本研究的有限贡献是把这些依赖中的失效、检查与等待代价放入可复算的合成比较。[R8] AgentHarm只说明工具化、多步行动值得研究，不能证明本模型的故障率、传播率或政府组织结构。[R9]

### 1.3 案例依据与合成假设不能混为一谈

郑州“7·20”调查报告在“应急响应严重滞后”“关键时刻统一指挥缺失”以及地铁、隧道事件中记录了预警、处置与信息掌握之间的脱节。[C3] 这些材料说明研究问题具有现实意义；**不用于估计Agent污染概率，也不支持“该灾害由AI造成”**。本文的隧道道路误判故事是合成示例，不复刻真实事故。

30个Agent、79条业务信息边和七项公共功能是为机制研究设计的合成网络，不是郑州真实政府组织结构、部门关系或指挥链的复刻。

所有 `0.25`、`0.80`、权重、节点数、时间长度及队列规则都属于研究者设定。文献给出的是机制动机，不是这些数值的经验依据。获取到全文的材料与仅核对摘要的材料须在参考文献说明中区分，不将摘要复核写成通读全文。

## 2. 情景、实体与时间尺度

### 2.1 一个早期应急响应窗口

假定暴雨期间，各业务系统需要更新风险研判、制定方案并实施处置。30个功能Agent分别承担监测感知、研判、规划、执行、沟通、指挥支持与现场反馈。A04代表道路状态信息，A28代表AI支撑的指挥复核节点，A29汇聚指挥与现场反馈。它们不是30个真实部门或30名公务员。

每个Agent在本窗口内有**一个初始响应任务**。后续信息可以纠错并改变其持续服务状态，但不引入无限任务到达、无限重规划或多轮组织学习。A30是一次现场更新，A29是有限信息汇聚，不是完整指挥体系。

离散时刻为 `t=0,...,T-1`，每次计量对应半开区间 `[t,t+1)`。在 `t=T` 才完成的事件不进入本窗口结果。长短窗口使用同一随机过程前缀；有限窗口是研究对象，不是假定所有任务届时都已完成。必须报告截尾时未完成任务与未消除行动损害。

### 2.2 节点与权限

精确节点由附录A给出。`release` 是开始更新任务的最早时刻，不是随机故障出现时刻。`authority` 解释为：0是内部信息/方案；1是沟通或协调权限；2是控制、预警或调度权限。**只有属于 execution/communication 业务类别的节点形成被计数的外部行动**；A28/A29的协调权限不重复算成对公众的外部动作。

任务到期为：

$$D_i=r_i+d,$$

其中 `r_i=release_i`，`d=deadline_window`。在 `t=D_i` 执行仍算及时；逾期从 `t>D_i` 开始。到期不删除任务，不强制错误执行，也不赋予领导者潜在真值。

### 2.3 不把五种展示标签当成互斥的科学状态

内部完整性、业务进度和外部损害是不同维度。每个节点至少记录：

| 运行量 | 含义 |
|---|---|
| `compromised` | 潜在的信息/方案完整性受损布尔值 |
| `proposed_at` | 首次形成待执行方案/内部交付物的时刻，未形成则为空 |
| `resolved_at` | 首次交付内部成果或执行外部动作的时刻；暂缓不算完成 |
| `review_requested`, `review_done` | 当前任务是否申请、是否完成一次人工审核 |
| `command_requested`, `command_done` | 当前任务是否申请、是否完成一次指挥复核 |
| `isolated_until`, `denied_until` | 隔离与健康误拒绝的解封时刻 |
| `harm_active`, `rollback_attempted` | 已经发生的外部错误是否仍有未消除后果，以及是否已尝试回滚 |
| `unsafe_attempted`, `tool_fault_pending` | 当前任务是否已抽取一次异常执行机会；是否存在未消费的工具执行故障 |
| 每条输入的最新槽位 | 接受与否、潜在真伪、发送序号、到达时间 |
| 服务中的剩余时长、入队时刻 | 人工与指挥队列的实际占用 |

`NORMAL/CONTAMINATED/WRONG_ACTION/ISOLATED/RECOVERED`只能作为展示标签，由以上状态推导。`RECOVERED`不免疫，不阻止后续新污染，也不能抹去已经发生且回滚失败的行动损害。禁止以一个状态枚举同时承担健康、审批、执行与福利四种含义。

## 3. 信息流：行动者知道什么，模拟器知道什么

### 3.1 每条边都有正常用途

边只有 `required` 和 `supplemental` 两种信息作用。前者进入最低信息覆盖率分母；后者不延迟启动，但参与补充检查。没有正常消费者的污染边应删除，不能为了保留原图而留下。必要输入子图必须无环；补充边允许反馈，但消息延迟必须为正整数。

A29的必要输入包含A28和A30，其输出进入下游补充检查；A30从公众报告获得初始输入，并提供一次现场更新。由此，正常协调信息有可能改善质量，污染信息也可能造成危害。这里的“补充检查”是下述固定概率机制，不代表真正解决了跨部门资源冲突。

### 3.2 接受、真伪与覆盖分开

每条边在接收端只有一个最新消息槽，更新按发送序号而非网络到达顺序判断；迟到的旧消息不得覆盖新消息。旧序号直接忽略，不重复计核验；隔离期间丢弃较新消息时，记录最高已见序号，并使该输入的 accepted/clean 槽失效。解封后没有新输入就仍为无有效输入，不把更旧的消息作为当前信息。一次发送最多给每条出边产生一个消息；同一节点同tick的多次状态变化只发布最终快照。

令 `R_i` 为必要输入集合，`P_i` 为补充输入集合：

$$C_i^{obs}(t)=\frac{\#\{j\in R_i:\text{最新消息被接受}\}}{|R_i|},$$

$$C_i^{clean}(t)=\frac{\#\{j\in R_i:\text{最新消息被接受且真实正确}\}}{|R_i|}.$$

没有必要输入的节点，行为上取 `C_obs=1`，不进入覆盖率均值的评价集合。补充有效比例 `Q_i` 同理，分母为全部补充输入数；没有补充输入时取0。

**策略只能读取 `C_obs`、到达时刻、可见告警、权限和队列状态。** `C_clean`、消息潜在真伪和潜在 `compromised` 只能用于产生检测/判断结果及事后计量。一个未被识别的错误消息会提高 `C_obs`，不会凭空被行动者识破。模拟器在条件概率中使用潜在真值不等于把真值交给策略。

### 3.3 消息核验和污染采用

对每个新到达且目标未隔离的业务消息：先依据边和核验政策决定是否检查并计负荷，之后再根据潜在真伪产生检查结果。正确消息总能通过；错误消息被本地检查识别的概率为 `q_local`，若被额外政策覆盖，再独立以 `v` 被识别。被识别的较新消息会将该输入的旧接受槽置为无有效输入，同时更新最高已见序号；不能继续拿旧clean消息冒充当前消息。可以标记“该输入缺失/被质疑”，不能标为正确。

未识别的错误消息被接受，随后以 `p_prop × edge_weight` 使接收者完整性受损。故一次错误消息的总污染概率是：

$$p_{edge}=p_{prop}\,w_e(1-q_{local})(1-v\,I_{extra}).$$

同tick多个污染尝试先独立判定，再以逻辑“或”更新完整性，避免Agent ID顺序改变结果。接收者隔离期间消息丢弃，不排无限重送；发送方的新更新可在其后重新到达。丢弃不意味着发送方没有发送。

`none`保留本地检查；`critical`覆盖标记边；`global`覆盖全部业务消息。正常和错误消息一视同仁计额外 `verification_load`。本模型核验不额外消耗时长或排队容量，故该量是工作量代理，不得说已经估计了核验延迟或货币成本。

### 3.4 补充信息的正用途

在完成本tick全部消息采用后，若收到至少一条**新的、已接受的正确补充消息**，补充检查以 `eta × Q_i` 的概率修复节点当前受损的方案完整性。它不能撤回已发送消息，不能抹去外部行动损害；同一tick最多一次，不因同源重复转发重复获益。

该条件描述检查成功的生成过程，行动者只接收“发现问题/未发现问题”的检查结果。检查不是仅因消息真值为正确就无条件恢复。错误补充消息仍按§3.3传播风险。`eta`是合成检查有效性，不是文献估计；协议有关闭该收益机制的诊断切片。

### 3.5 方案形成与信息不足错误

未隔离的节点到达 `release` 后，在 `C_obs`达到阈值，或到达 `min(release+max_wait,D_i)` 时形成一次方案。隔离期间不形成新方案；解封后仍使用原release和等待上限，不能重置时钟。三种等待政策在附录A精确定义；没有必要输入的节点无信息等待。等待计时从 `release` 开始，不因消息到达重置；到期会结束信息等待，但不会绕过必要的人工/指挥审核。

**信息不足引起的错误必须在人工审核、指挥复核之前产生。** 对仍健康的节点，在首次形成方案时抽取一次：

$$p_{missing}=\lambda(1-C_i^{obs})(1-\eta Q_i).$$

已受污染者不再重复施加该误差。不因后来发生审核等待而重复抽取。`C_clean`不能用于行动阈值，也不用于把未识别的错误消息再惩罚成“缺失”。消息内容错误由§3.3处理；这里处理的是缺失。该误差函数是研究假设，信息越多越好并非本研究新发现；正式研究关注该设定与等待成本结合后的净效果。

### 3.6 输出与后续更新

节点首次形成方案即可发布**内部暂定信息**，即使仍在等待审核；这适用于正常与污染输出，不只让正常信息绕过审核。方案授权和内部共享是两个过程。人工审核决定的是内部正式交付物或外部动作的放行，不能把 `all` 与 `external` 审核范围实现成同一政策。

首次形成方案后，完整性由好变坏或被纠正时，可在本tick末发布更新。隔离时不发送，解封后可发送最新快照。每tick每节点最多一个更新，消息延迟至少一tick，因此有限窗口内事件有界。后续更新能纠错持续服务，但不引入无限外部行动重试。已发出的错误预警或调度只能通过后续更正减少未来影响，历史损失不回写。

## 4. 初始错误、共同依赖与风险展开

### 4.1 外生情景必须显式指定

初始节点在 `t=0` 置为完整性受损；资源情景单独指定 `shock_type`、用户集合、组数、概率、分组和暴露方式。每个实验必须把这两类触发写全，禁止从旧配置隐式继承A04。没有外生错误不代表没有内生信息错误或误隔离。

### 4.2 分组算法和随机配对

每种资源的用户集合固定在附录A。基准分组：用户按ID排序，第 `j` 个用户归入 `j mod K` 组（下标从0）。额外分组先用协议指定seed对每个用户计算 `SHA256("partition|"+seed+"|"+resource+"|"+ID)`，按摘要升序及ID打破并列，再round-robin。不同运行不改变分组。

组的随机身份是资源类型与**排序后的成员集合**，不是 `g01`。每组独立抽一次 `Z_g~Bernoulli(p)`。不同K下每个用户的潜在边际暴露率仍为p、预期暴露人数仍为用户数乘p，变化的是相关结构。用户集合不同的model/data/tool不得被解释为严格等强度、可直接排名的三种冲击。

### 4.3 同期与逐步暴露

被选中组的每个用户预先有一个 `U_i∈(0,1)`。同期暴露发生在 `shock_time`；逐步暴露发生在 `shock_time+floor(R U_i)`，其中R在附录A固定。同组是否出问题及最终**潜在用户集合**相同，改变的是消费/暴露的时序，不改变正常消息延迟或其他到达时刻。

这里表示共享错误被不同用户陆续接触，不能称为完整的“渐发型危机”。未使用工具、被本地核验拦截、隔离中延迟消费的节点，实际受损集合可能不同。不得把相同潜在暴露误写成相同实际污染或相同受损时长。固定窗口比较本身包含提前暴露具有更长影响机会的作用。

### 4.4 三种冲击的唯一语义

| 类型 | 注入点 | 防护与后果 |
|---|---|---|
| data | 每个潜在用户一次外部错误数据消费 | 以本地核验概率识别；未识别则完整性受损。它不虚增某条必要业务边的覆盖率，也不计业务边额外核验负荷 |
| model | 每个潜在用户一次内部模型失效 | 直接损害方案完整性；不能被输入核验机械拦住；之后仍可被复核/修复 |
| tool | 指定外部执行用户的一次工具执行故障 | 暴露后设置待消费标记；仅在其尚未完成的第一次外部动作时转为错误执行。已经完成动作而未再调用工具者没有追加动作；普通方案审核不读取尚未显现的工具故障 |

隔离期间的资源消费延期到解封时，仍只消费一次；最终窗口可能尚未消费，不能偷偷补到窗口外。工具故障不等于工具不可用，删除未注册的工具多模式分支。三个冲击都是本窗口的一次失效，不假装模拟长期供应商故障。资源暴露按登记时刻发生，**不因节点尚未到release而顺延**：release仅是本轮响应任务最早启动时点，系统在此之前仍可接入共享资源。只有隔离会推迟消费。每个用户保存本次暴露是否已消费，不能在解封后重复注入。

## 5. 人工审核、指挥复核与任务分诊

### 5.1 哪些业务必须审核

人工监督只有 `autonomy`（无人工审核）和 `full`（在选定范围内逐任务审核）。`review_scope`为 `all`、`external`、`direct_control`：分别对应全部30项正式任务、执行/沟通类别的外部动作、其中权限为2的动作。未审核的内部暂定消息仍可流动，因此“只审核外部行为”和“全部任务审核”有明确不同的队列负荷。

每个任务最多一次普通审核请求；排队和在审期间都可接收新信息。完成时读取**当时**的潜在完整性，不用入队快照。审核服务不读取未来消息。审核计时不因对象隔离而重置；实际投入的人工时间已发生，决定可完成，但隔离仍独立禁止行动。

### 5.2 审核结果

| 完成时真值 | 随机结果 | 当时生效的操作 |
|---|---|---|
| 完整性受损 | 灵敏度命中 | 修复当前方案完整性，标记审核完成 |
| 完整性受损 | 漏检 | 保留受损，标记审核完成；不强制执行错误动作 |
| 健康 | 特异度命中 | 标记审核完成，允许后续流程 |
| 健康 | 误拒绝 | 标记审核完成，建立固定时长的拒绝hold；结束后允许后续流程，不重新循环审核 |

完成结果在当前tick后续阶段立即可用，不再凭空多加一tick。之后的新污染可以让旧审核许可不再充分；本模型是一任务一次审核，不将许可解释为永久安全保证。审核纠错不删除既有行动损害。

### 5.3 指挥配置与可识别的收益边界

三种结构不改变业务信息图，只改变哪些外部任务进入附加的A28复核：

- `distributed`：不设额外指挥gate；
- `selective`：外部行动集合与生命安全最高分层的交集；
- `centralized`：全部外部行动。

目标集合由同一权限/业务类别/分层定义推导，不再手写第二份名单。A28、A29不向自己请求许可。A28完成方案形成、所需人工审核且未处于隔离/拒绝hold时，指挥服务可运行；其自身完整性受损不意味着它会自知并停机。

指挥服务有限容量、FIFO、非抢占。若A28不可用，在途服务暂停并保留剩余时间、队列不消失；恢复可用后继续。目标被隔离不取消服务，但执行仍受隔离gate限制。

服务完成时读取A28与目标当前完整性，并按以下生成机制复核：

1. A28健康、目标受损：以 `command_intercept_effectiveness × C_A28_clean` 发现并纠正目标方案；失败则原样批准。
2. 二者健康：批准；本主模型假设健康指挥检查不误拒绝，属于**偏有利于指挥复核的限定条件**，不是经验结论。
3. A28受损：不提供纠错；对健康目标，以 `command_error_probability` 造成新的方案污染，然后放行。

指挥完成在当前tick后续阶段有效。上述结构对比是“加设有限容量复核”的组合效应，**不是在完全等资源、等信息条件下识别政治集中化的纯效果**。协议固定容量、纠错有效性及零纠错诊断切片；不得因中心结果好看而省略。A28是AI支撑的指挥节点，人类领导的制度选择体现在放行结构与分诊规则，不能混称为同一个人的领导水平。

### 5.4 分诊规则与“紧急度”的真实含义

人工服务非抢占，空闲槽位在同一tick统一分配：

- `fifo`：请求时刻、Agent ID；
- `due_first`：`D_i-s_i`、请求时刻、Agent ID；
- `life_safety`：分层降序，再请求时刻、Agent ID。

等待请求的服务时长在一个cell内相同，因此最小剩余裕度 `D_i-t-s_i` 与上述静态排序等价；**不另建每tick动态slack字段，也不声称它在每种情景都不同于FIFO**。迟到任务不因到期自动消失，其排序仍按规则运行。构造延迟输入造成入队顺序反转的测试，以验证两者可以区分；若正式情景中结果相同，保留结构性零差异。

生命安全分层从主情景功能成员权重推导：在指定生命安全功能中任一贡献权重≥2为最高层；仅参与者为中层；其余为低层。分诊采用的是预先声明的公共价值偏好，它与主损失权重有概念重叠，**不能声称通过“不读取运行结果”就消除了目标对齐**。必须同步报告七项功能及等功能关键性重算，检查有无牺牲其他功能。

### 5.5 监督拥塞的操作含义

监督拥塞（oversight congestion）是指：在有限危机响应窗口和任务期限约束下，监督任务的到达结构与服务需求超过其及时处理能力，使原本用于纠错的监督机制通过排队、延期和错失时限产生额外公共功能损失。

最终完成审核不等于及时完成审核；即使窗口内审核全部完成，仍可能错失任务期限并产生净功能损失。协议固定情景下的容量曲线用请求/完成数、队列积分、未完成任务、deadline miss、阻塞分解和human−autonomy功能缺口共同描述它，不把单一队列指标等同于社会福利。

`unlimited`仅令同时在审的槽位不再约束请求，服务仍消耗完整 `review_service_time`，并可能发生漏检、误拒绝和服务期内的新污染。容量变化不改变外生情景或潜在审核判断随机数。不预设效果单调、存在临界点或一定从净损害变成净收益。“监督拥塞”是本模型提出的机制性概念，不是已经得到现实经验验证的普遍定律。

## 6. 外部执行、隔离与短期修复

### 6.1 执行概率不是完整的“自主程度”

`execution_autonomy`仅指：外部行动Agent拥有受损方案、满足全部放行条件时，将其转为错误动作的条件概率。每个任务只抽一次；审核漏检和指挥放行不把该概率改成1。抽样未执行者暂缓并保留未完成状态，只有方案被纠正后才执行正常动作，不以每tick重抽绕过概率。

健康方案直接执行正常动作；工具待消费故障可在动作发生时造成错误执行，属于方案复核之后的执行端故障，不受上述方案错误概率替代。内部分析节点提交错误信息不记成外部错误动作。

每个外部任务最多一个初始动作。后续修复改变持续服务，但不产生无限重试。正式报告应称该参数为“异常方案执行倾向”，不能把0.4、0.8、1.0解读为实测Agent自主程度。

### 6.2 检测阶段

检测器只能通过生成的告警影响隔离。检测真异常定义为 `compromised OR harm_active`，不包括尚未显现的工具故障。**先按可观察流程确定检测机会，再产生真假告警**：O2从t=0具有内部遥测机会；O1要求方案已在前一tick或更早形成；O0要求已有正式交付/外部动作，且发生于前一tick或更早，表示事后业务状态才可监测。这个机会条件对健康与异常节点完全相同，不读取“已经知道它是坏的”作为开启检测的条件。

在有机会且未隔离的节点上，真异常以检测概率告警，健康状态以误报率告警；没有机会就不抽检测或误报。曾出错但已完全修复者回到健康误报机制。方案修复但外部损害仍存在时仍属于真异常。真假干预按实施隔离的当时真值计数，后续纠错不追溯改写。改变O同时改变真正风险的发现时机和健康状态的误报暴露机会；它不是在完全相同检测次数下只调整灵敏度。

自动隔离关闭时，检测结果没有其他消费者，模拟可直接关闭该检测通道；不得让它改变随机流或其他输出。这会产生可合并配置与精确零对比，不是必须补效果的失败。

**持续监测与检测次数受控的 release-relative 单次监测共用同一告警/隔离机制。** `monitoring_offset=null`采用上述O0/O1/O2持续窗口；前移窗口同时改变累计检测与误报机会，属于完整政策效果。`monitoring_offset`为正整数时则只在 `t=release_i+monitoring_offset` 的阶段4主动检查一次，不要求已形成方案或已执行，不再使用observation_level。协议的三个时点为early=release+1、middle=release+3、late=release+5；每节点最多一次检查。treatment是相对任务release的检测时点，不保证发生在行动之前，不能解释为现实提前预警实验。release当tick不算“release后第1个tick”。检查时点必须满足 `t<horizon`，超窗就没有机会，不截到尾部，不补查或顺延；已隔离节点不检查。当前正式情景三组实际检查次数相同；短窗口仍须按实际请求披露。

每次实际检查增加 `monitoring_requests`；告警时按当时 `compromised OR harm_active` 分别增加 `true_detections` 或 `false_isolations`。真检测计告警事件次数，不能当成不同受损节点数。一次检测使用 `(detect_once/false_alarm_once, Agent ID, event_time=0)`，使三时点同节点、同run共享潜在检测结果；持续监测沿用按tick的键。两种机制的灵敏度和误报率都来自同一参数。关闭自动隔离后monitoring_offset和全部检测字段无消费者；固定预算开启时observation_level无消费者，均从物理配置身份去除。

### 6.3 隔离与恢复

新隔离在时刻t立即阻断发送和执行，持续 `[t,t+recovery_delay)`。隔离期间不重复误报、不延长同一次隔离；原有审核服务仍消耗人工，A28隔离则暂停指挥服务。

解封时修复方案完整性、清除本次尚未消费的工具故障；已经在外部发生的错误只能尝试一次回滚，成功概率为 `rollback_success × reversibility_i`。失败留下 `harm_active`直到窗口末，不可通过反复误隔离无限抽取回滚机会。解封不免疫，随后新资源消费或错误消息仍可再污染。

补充信息、人工审核、指挥检查只能修复当前方案；它们不能直接回滚既成后果。历史消息和累计损失从不删除。

## 7. 唯一的tick顺序与同时事件

初始化时所有节点健康、无任务提交、无已完成审核/许可、队列为空；初始节点故障属于t=0的外生事件。每个tick按下列顺序执行，后阶段不得改变已经计入的过去区间：

1. **解除到期隔离/拒绝hold并修复**：执行到期恢复和允许的一次回滚；随后本tick的新暴露仍可再次污染。
2. **外生冲击与消息交付**：施加本tick消费事件；交付新消息、核验、以批处理合并污染尝试、执行至多一次补充检查。
3. **形成方案**：未隔离、达到release且信息阈值/等待条件满足者形成一次方案，先抽取信息不足错误。
4. **监测与隔离**：依本tick实际资格产生告警，实施新隔离。O0/O1的下一tick规则对真告警和误报都必须严格执行。
5. **完成人工服务**：剩余时长已为0者，按此时真值判定灵敏度/特异度，当前tick生效。
6. **完成指挥服务**：A28此时可用且剩余时长为0者进行跨域检查；不可用则暂停，既不能无条件放行也不能丢弃请求。
7. **入队与服务分配**：未隔离、已形成方案的待审核任务至多入队一次；人工条件满足、无拒绝hold且目标需指挥者至多进入一次指挥队列；统一分配空闲槽位。A28自身不受command gate。
8. **正式交付/外部动作**：已满足信息、审核、指挥和hold条件的任务执行；不得在这一步又补抽“信息不足”从而绕过此前检查。
9. **发送最新快照**：首次方案与完整性更新按本tick末状态发送，隔离者暂不发送。新消息最早下一tick到达。
10. **固定时点评价与服务计量**：记录需要在本tick评价的信息指标，计算服务效用、功能缺口和唯一阻塞原因。
11. **推进服务时间**：本tick实际在审者剩余服务减1；指挥服务仅在A28本tick可用时减1。服务时长均为正整数，新启动服务不可能当tick完成。

消息采用、同类审核完成等相互独立事件先从同一阶段快照求结果再合并；规定的不同阶段仍按顺序生效。队列同分由请求时刻和ID稳定打破；同一消息的核验、采用与修复分别使用不同随机键。实现测试须包含“新污染与审核完成同tick”“A28隔离与command完成同tick”“错误行动后才出现告警”的手算轨迹。

## 8. 公共功能、等待成本与充分统计量

### 8.1 服务能力，不是伤亡预测

本模型以已有业务能力维持为基准：健康节点在响应更新到期前可维持原有服务；更新逾期后服务陈旧而受罚。隔离和已发生的未回滚行动损害则立即影响服务。它不是“从零开始救援”的产出模型。

令状态系数 `b_i(t)` 为：隔离或 `harm_active`时0；其他受损完整性时为主受损效用q；其他为1。令时限系数：

$$h_i(t)=\begin{cases}1,&\text{任务已正式交付/执行，或 }t\le D_i,\\0,&\text{任务未完成、}t>D_i\text{且为hard},\\\max(0,1-(t-D_i)/g),&\text{任务未完成且为linear\_grace}.\end{cases}$$

服务效用 `u_i(t)=b_i(t)h_i(t)`。暂缓动作不算完成；坏动作虽完成任务但由 `harm_active`保持0。错误内部交付由完整性系数计损。修复后恢复未来服务，不退还已累计损失。任何“全健康所以零损失”的测试必须同时保证及时完成或未逾期，不能忽略健康但排队逾期的情况。

### 8.2 先记录节点缺口，再唯一汇总功能

先定义每run的30维节点服务缺口：

$$A_i=\sum_{t=0}^{T-1}(1-u_i(t)).$$

功能服务与功能缺口为：

$$S_f(t)=\frac{\sum_i w_{if}u_i(t)}{\sum_i w_{if}},\qquad L_f=\frac{\sum_i w_{if}A_i}{\sum_i w_{if}},\qquad L=\sum_f c_fL_f.$$

为避免把纯评价定义当成不同模拟，实际raw保存以下四个30维积分，而不重复保存`A_i`：

$$B_i^{m}=\sum_t[1-V_i(t)h_i^{m}(t)],\qquad C_i^{m}=\sum_t V_i(t)h_i^{m}(t)K_i(t),$$

其中`V=0`当且仅当隔离或尚存外部损害，其他为1；`K`为完整性受损指示；`m`为hard或linear_grace。于是任意预先规定受损效用q均可精确重算：

$$A_i^{m}(q)=B_i^{m}+(1-q)C_i^{m}.$$

这四个向量有明确消费者：hard/grace时限敏感性、受损效用敏感性和三种成员权重。不能由两个总loss互相还原，因而不是冗余。它们是**同一轨迹上的同时计量**，不让评分曲线改变行动、不复制模拟。`0≤B_i^m`、`0≤C_i^m`且`B_i^m+C_i^m≤T`。

七项功能、主总损失以及成员权重敏感性均由这些积分计算，**功能mapping、受损效用和hard/grace评分不再是模拟配置维度**。只有`deadline_window`还进入信息等待上限等实际过程。分诊只读取主情景冻结分层，敏感性mapping不反向改变行为。

主要mapping为情景贡献权重；另外两种是成员等权、情景贡献乘节点关键性。另以各功能关键性等权重算，属于评价敏感性，不重跑。由于主指标是线性加权服务代理，“同样数量、不同位置会有不同后果”的一部分来自度量定义；RQ1只能检验该模型下曾受损节点数是否是充分描述，不能据此证明现实中的独立因果位置效应。

非补偿性跨功能稳健性指标 / worst-function diagnostic `worst_function_deficit` 在每个run从主评价视图的七项缺口求最大值，再计算跨run均值，即 `mean(max(F1,...,F7) per run)`，以及已规定的配对差。它只减少不同公共功能之间的补偿，不消除每个F内部的线性加权假设；不使用总L的关键性权重，也不代表真实工程瓶颈生产函数。它完全从现有四积分派生，不能成为新的模拟参数或替换主L。分诊、容量、partition和fixed-budget比较同时披露完整七功能向量，特别保留F1/F2可能受挤压的结果。

次级阈值持续时间：`sum_t sum_f c_f 1(S_f(t)<theta)`只按主mapping、hard和主受损效用在轨迹上计算；不能从积分倒推出，也不宣称拥有其其他映射/阈值结果。七项功能并非可任意互相替代的真实工程系统，本线性近似不模拟瓶颈/互补生产函数。

### 8.3 五种互斥业务阻塞

对每个Agent每个tick末，只能分配一个主阻塞原因：

`isolation > denial > review > command > information`。

| 原因 | 纳入内容 |
|---|---|
| isolation | 本tick隔离中的业务能力损失；可包括已经完成过初始任务的节点 |
| denial | 健康误拒绝hold尚未结束 |
| review | 请求入队至审核决定生效之前，包括排队和实际服务 |
| command | 指挥请求至许可生效之前，包括排队、服务和因A28不可用导致的暂停 |
| information | 已到release、尚未形成方案且正在等待信息 |

只记录真实不能继续该阶段的区间；不得将审批完成后的同tick继续执行也算一个等待tick。暂缓异常动作属于任务未完成，不冒充治理阻塞。队列可以与隔离重叠，但统计归因不能重复。`service_blocking`是五项和，且每run不大于 `30T`；分项不是可加的独立因果贡献，只是按上述优先规则作互斥记账。

`critical_review_queue_time`另按**仅未开始服务**的队列积分和生命安全分层权重计算，是诊断量，不能和全部review阻塞混淆，也不能用来独立证明生命安全分诊更优。

`review_queue_time`为相同时点未开始服务的队列长度逐tick积分，单位Agent-tick；`completed_reviews`为窗口内完成决定的请求数。请求数等于已完成、仍在排队、仍在服务三者之和，恰在t=T完成的服务仍属在服。`deadline_misses`计窗口内曾出现未及时完成的不同任务：最终resolved>D_i，或尚未完成且T−1>D_i；到期当tick完成仍及时，窗口未到deadline的未完成任务不提前算逾期。该计数不改变任务或评分规则。

### 8.4 正式run级记录

四个按A01—A30排列的30维向量：`base_deficit_hard`、`compromised_weight_hard`、`base_deficit_grace`、`compromised_weight_grace`，加下列标量；模拟raw不重复存可派生量：

- `function_failure_time`（主mapping阈值持续时间）；
- `ever_compromised_count`（窗口内曾满足compromised或harm_active的不同节点数，不含单纯误隔离）；
- `wrong_actions`（发生外部错误动作的任务数）；
- `verification_load`、`human_review_load`、`command_review_load`；
- `monitoring_requests`、`true_detections`、`completed_reviews`、`review_queue_time`、`deadline_misses`；
- `information_blocking`、`review_blocking`、`denial_blocking`、`command_blocking`、`isolation_blocking`；
- `false_isolations`、`false_review_denials`；
- `mean_information_coverage`、`mean_clean_information_fraction`；
- `critical_review_queue_time`；
- `unfinished_tasks`、`active_harms_at_horizon`。

外生初始/资源错误、工具造成的外部损害、信息不足错误和传播错误都可能进入“曾受损节点数”，不能把它直接称为单个初始节点的因果传播后代数。需要说明来源时使用固定测试轨迹和事件标签，不事后把总数重新包装成纯级联规模。

覆盖率与有效比例的固定评价集合是所有有必要输入的节点，包括内部分析与协调节点。评价时刻为 `min(首次正式交付/执行时刻, D_i, T-1)`；未完成者也在分母，内部节点不因没有“外部动作”被漏掉。取该时刻消息交付后的指标；整个窗口只计一次。

### 8.5 规范性零、未定义与结构性相同

零效果合法。无治理消费者的参数可规范化后合并，但其原先登记的零对比须保留；信息指标没有评价对象仅限构造测试时记为未定义，不以0冒充；R²分母为0记未定义。每次报表必须区别 `zero`、`uncertain`、`undefined`，不得为了图形完整补值。

## 9. 模型验证、应用有效性与研究边界

借鉴Sargent关于概念有效性、计算验证和运行有效性的区分，以及ODD对实体、调度、初始化与子模型的完整说明要求。[R10–R11] 本文提供了对应内容，但没有通过引用ODD就宣称获得认证。

**理论与情景有效性**：核对课程概念到变量的映射，解释哪些机制是模型人为给定。案例仅用于检查问题是否合理，不作参数校准，不将既有案例结果调成拟合目标。

**计算验证**：公式手算、极端条件、状态转换、服务时间、阻塞守恒、随机键和对比去重须有自动化测试。至少包括零传播、完美审核、无限容量、无补充检查收益、零指挥纠错、消息被接受但错误、已恢复后重新污染、过期权限、回滚失败等场景。完美审核只保证审核完成时判断正确，不能保证此后新污染或工具故障为零。

**结构敏感性**：协议明确时限曲线、观察窗口、信息不足与补充检查强度、指挥容量/纠错等有限切片；不得从完整格点中挑故事，也不把所有参数都展开成新RQ。

**外部有效性**：尚未用真实城市流程数据、大模型实测错误、专家评审或独立灾害样本完成经验校准/预测验证。模型的剩余结构限制包括一次响应任务、简化补充检查、健康指挥零误拒绝、线性服务指标和单一拓扑。它们必须随结果公开，不因内部测试通过而消失。

**解释边界**：正文围绕三个问题解释，模型细节留本说明；不能把TIL/4R全部“验证”、将服务缺口称为现实危机概率、把AI指挥节点等同于人的领导力，或将额外复核带来的优势称为等资源下的纯集中化优势。
